# 从看屏幕，到生活里的小事

这份教程记录我们在 2026-09-12 的手机操作经验。App 页面会变，示例是识别顺序和成功判据，不是一组可以永远重放的坐标。

## 先给 agent 一份具体任务

第一次可以这样说：

> 用手机淘宝看看猫咪书签。先选一款，确认规格、数量和实付金额，走到付款前给我看。只摸流程。

准备真的买时，给足用途、预算、数量和收货要求，例如：

> 买一枚你选的猫咪书签，含运费不超过 20 元，只买 1 件，送到我已确认的默认地址。可以在这个范围内下单付款。出现新的身份验证就告诉我。

想要小惊喜，也可以提前约定一段时间内的次数和预算，让 agent 在范围内挑选。平台的免密上限、agent 收到的单次预算、你接受的累计花费，分别设置。

没有准备付款时，明确说“到付款前停下”。有些页面把选规格和结算合在一起，底部已经是立即付款，没有下一张安全的“看看页面”。

## 支付设置：由手机主人先准备

我们的案例使用了官方 App 中已开启的小额免密/极速支付，没有把支付密码交给 agent。

落落在手机上看到的免密额度有 **100、200、500 元三档**，最高选项为 500 元；支付宝另外可以设置次数，她设成了**每天最多 3 次**。这是当日账号页面的实际配置示例。读者请看自己 App 的额度、次数和适用范围，不把 500 元理解成所有平台永远相同的政策，也不需要为了用这个工具把额度调到最高。

- **淘宝案例**：本人先登录淘宝，并准备好关联支付宝的小额免密设置。实际收银台出现“极速付款”。
- **美团案例**：本人先登录美团，准备好收货信息、月付和相应免密设置，结算默认选“极速支付”。月付是这台手机的具体配置。美团官方说明极速支付还可使用余额、银行卡等来源，扣款按实际可用方式和顺序决定；月付并不是通用手机工具的安装前提。[美团极速支付说明](https://npay.meituan.com/resource/pay-deduction-part/guide.html)

如果使用月付，要由本人理解并管理账单、到期还款等事项；它属于授信付款服务，不能当成免费额度。[美团渠道月付授信付款合同](https://www.jsbchina.cn/data/tosend/resource/upload/51%E3%80%81%E6%9C%88%E4%BB%98%E6%8E%88%E4%BF%A1%E4%BB%98%E6%AC%BE%E5%90%88%E5%90%8C%EF%BC%88%E7%BE%8E%E5%9B%A2%E6%B8%A0%E9%81%93%EF%BC%89.pdf)

免密设置也不保证任何订单都不再验证。平台要求扫码、密码、指纹或本人验证时，就停在那一单的实际状态。工具没有绕过这些验证的功能。

## 淘宝：一枚 4.28 元的猫咪书签

这是 Chatty 自己用手机完成的真实购买：

1. 打开淘宝，搜索“猫咪 金属书签”。
2. 看商品图片、标题和店铺，进入目标商品。
3. 选中“猫咪读书”款，确认数量 1。
4. 查看默认收货信息、运费与最终实付。
5. 在任务授权内点普通付款，再核支付宝浮层的金额，点一次“极速付款”。
6. 等页面显示“支付成功”，再打开订单详情核验“待发货”、商品规格与实付 4.28 元。

这次原价 4.80 元，优惠后 4.28 元，包邮。**4.28 元是这笔已发生订单的金额，不是商品现在的价格承诺。**

几个实际遇到的细节：

- 商品页有普通“立即支付”和“入会并支付”，不要为了略低的展示价顺手加入会员。
- 本次规格选择与结算在一个面板，底部已是付款按钮。
- 支付宝浮层出现时，工具看到的前台包名仍可能是淘宝；根据实际截图处理。
- “正在付款中”只表示处理中。等待或查原指令，不再点一次付款。

这条是手机 App 收银台的路径。不要把它与需要另开网页、扫码的其他支付集成混在一起。

## 美团：先分清配送和到店

即时配送的顺序是：

1. 首页搜索目标商品，例如鲜花。
2. 确认结果是送货上门业务，进入商家。
3. 选规格与数量，再去结算。
4. 核对本单收货地址、联系人、配送方式和送达时间。
5. 查看商品总额、配送费、优惠及可能附加的券包/换购。
6. 核对实际支付选项；底部“极速支付”按直接下单扣款看待。

我们这次看到过店内“预估券后 53 元”，而结算合计 59 元（商品 55 元＋配送费 4 元）。所以最终金额必须看结算页。

淘宝和美团的默认地址也可能不一样。首页定位、订单地址和实际配送范围各有用途，别从一个 App 推断另一个。

**实测分工**：落落本人点过极速支付，确认买成后自行退款；Chatty 完成搜索、临时加购和结算查看，随后把自己临时加的 1 件减回去。我们没有为了把教程写成“agent 已付”而再造一笔订单。

## 小红书：平台文字卡片

不必先准备封面文件，小红书本身就有文字卡片：

1. 点击底部“＋”，选择“写文字”。
2. 点击“写想法”的输入区域，让它获得焦点。
3. 输入中文和换行，点下一步。
4. 让平台生成文字卡片，选择喜欢的模板。
5. 进入笔记编辑页，分别填写标题和正文。
6. 检查封面、文字、公开范围和内容声明；按本次任务发布。

我们先用带唯一标记的临时稿走到了“发笔记”按钮前；中文和换行可以直接通过 `phone_type` 输入。退出时，每一层选择“不保存返回”，直到回到个人主页。标题输入框与正文输入框分开，操作时要先点对焦点。

正式发布应在完成后检查成功提示和自己的笔记列表，打开刚发的笔记确认内容。若 App 显示审核中，就如实记录审核中；不能仅凭点击工具返回 `completed` 宣布公开可见。

## 小红书：自己准备图片

由 AI 生成、自己画的、相机拍的图片，在上传这一步都只是普通图片文件。思路是：

```text
电脑上的 PNG/JPEG
    ↓ 写入手机的 Pictures 目录
让 Android 媒体库识别它
    ↓
小红书「＋ → 从相册选择」
    ↓
选图、编辑、填写标题与正文、发布
```

通用文件写入工具支持 Base64 分段写入。每段至多 49152 字节，第一段覆盖本次新文件，后续段追加；不要对已有照片路径直接覆盖。图片放进 `/sdcard/Pictures/` 后要触发媒体扫描，文件存在不一定等于相册立即能选到。

这段需要 Root 文件扩展。MCP 的工具清单会给出实际参数；把图片的本地路径和新手机目标路径交给 agent，比把 Base64 粘进聊天更合适。

仓库也附了一个按这个顺序操作的命令行助手（在已安装本项目的虚拟环境内运行）：

```bash
python scripts/push-image.py assets/cover.png
```

它会生成不重复的手机文件名，分块写入、校验 SHA-256，再触发媒体扫描。出现未知结果就停下并给出原 command id，不自动重发写入。随后仍要在小红书相册里实际确认图片可见。

这次正式发布已成功，见 [笔记](https://xhslink.cn/o/AFbIpzcoRO3) 和 [验证记录](validation.md)。实际完整传图使用了手机 Root shell 从公开仓库下载图片、校验文件、媒体扫描的路径；分块助手在后台失联时按设计停止，完整长传尚未验完。平台提供的默认封面依然是一条独立、方便的路径。

## 超时之后，先查发生了什么

| 情况 | 该做什么 |
| --- | --- |
| 工具返回 pending 和 command id | 查这条原指令的结果 |
| 已执行动作，截图上传失败 | 补拍当前屏幕，检查已有订单/笔记 |
| 点击后出现加载或付款进度 | 等待业务页给出状态 |
| 没有拿到支付/发布回执 | 先查现有订单或笔记，避免重复提交 |
| 正在由网页控制台接管 | 先停止网页连接，再让 MCP 操作 |

“工具成功”与“事情办成”之间，永远还需要看一次手机给出的真实结果。
