## 公共 APK 的一加实机验证

2026-09-12，用独立包名安装公共 APK，并连接独立测试服务完成了：

- 从手机设置页填写 HTTPS 地址和一次性配对码，服务端确认设备在线；无障碍截图和点按通过。
- 开启并验证 Magisk Root 权限。实际执行 `exit 7` 返回 failed、保留退出码 7，CLI 以非零退出，未把失败当成功。
- 公共网页接收并解码实时 H.264（本次 576×1280），点击网页“桌面”后手机返回桌面。
- 网页停止后，服务端直播会话清空，MCP 能继续截图，前台包名确认为系统桌面。
- 首次实机发现安装页固定高度误用了 px，已改为 dp 最小高度与自适应内容；更新后的 APK 重新安装，文字与按钮显示正常。

实机安装的最终 APK SHA-256：`fbb4b7e6ce09a3495508b4aa63bf403fef4bcd2853768004e7c2653e81fe5f7a`。

本次使用的是已有 Root 和基础后台配置的一加，不能据此保证所有厂商系统、干净新机、App 版本或长期熄屏待机都相同。实时控制验证了实际解码与桌面导航；其他触控方式仍应在自己的手机上做非付款任务确认。

## 自备封面与小红书正式发布

2026-09-12 14:25（UTC+8），Chatty 通过一加上的小红书 App 发布了 [给AI一台手机，我买了猫咪书签](https://xhslink.cn/o/AFbIpzcoRO3)，账号为「离落的小机」。

- 原生图像生成工具制作 `assets/cover.png`，文件写入手机 `Pictures/PhoneForAI/` 后由媒体扫描识别，小红书相册能看见并选中。
- 15 字标题和 522 字正文在发布前通过控件树逐字回读一致；填写了“含 AI 合成内容”声明。
- 点击一次“发笔记”，平台显示“发布成功”，关注页出现刚发的封面/标题；随后打开自己的笔记，确认公开可见、正文、Chatty 署名与 AI 内容标记。
- 复制并取得平台分享链接；取链接时临时粘入的输入框已清空，没有额外发表评论。

**传图中实际遇到的限制**：分块上传脚本写到 344064 字节后，ColorOS 熄屏/后台状态导致新伴侣失联，一条写入只留下 delivered 状态。脚本按设计停止，没有自动追加重试。我们补后台配置并恢复亮屏，将该未知指令明确放弃；最终改用手机 Root shell 从已公开仓库下载封面、断点续传并核对整文件 SHA-256，再进行媒体扫描。完整发布使用的是校验一致的图片。**因此本轮验证了分块写入和未知结果停止，也验证了 URL 下载→相册→发布；没有把分块助手的完整长文件上传记为通过。**

另一次熄屏测试中，公共版 `phone_wake` 返回了 SystemUI 黑图，需另行点亮屏幕后继续。首次使用先保持手机亮屏；后台持续传输与这台 ColorOS 的自动唤醒仍待后续完善，不能把“命令完成”当成“已醒来”。系统的跨 App 打开确认框也可能不接受无障碍点按，需要本人处理。

发布后补充的 operator 回执优化隐藏了 `files.write` 的大段 Base64，避免状态查询重复塞回整段文件；设备端仍收到完整原始数据，定向测试通过。GitHub 的 Android 与 Bridge/browser 两类检查均已通过。
